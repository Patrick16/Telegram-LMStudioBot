# Implementation Plan: Telegram-LMStudio Integration Bot

**Branch**: `001-json-short-name` | **Date**: 2026-04-11 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/001-json-short-name/spec.md`

## Summary

Build a Python Telegram bot that lets the authorized owner interact with a locally running LM Studio instance. Use the `lmstudio` Python SDK for inference (chat, image input, model info) and invoke the `lms` CLI via subprocess for model management (load, unload, list). Chat sessions with isolated histories, model settings, and system prompts are persisted as JSON on the local filesystem. Only a single, pre-configured Telegram user (bot owner) has access to any command.

**Scale/Scope**: 1 user, 1 machine, unlimited chat sessions (pruned manually)

## Key Design Decisions

### 1. LM Studio Integration Split
- **`src/lms/cli.py`**: Wraps `lms ls`, `lms ps`, `lms load`, `lms unload` via `asyncio.create_subprocess_exec`. Returns structured results; raises `LmsCliError` on non-zero exit.
- **`src/lms/sdk.py`**: Wraps `lmstudio.Client` for chat inference and image input. Constructs a `Chat` object per session history; streams responses back via async generator.

### 2. Session Store
- `SessionStore` is loaded from disk at bot startup and flushed to disk after every mutation.
- All mutations are synchronous (no concurrent writes possible since there is one user).
- Chat history is stored as a list of `ChatMessage` dicts; truncation is the responsibility of the SDK wrapper when the model's context window would be exceeded.

### 3. Authorization
- A single `require_owner` async decorator is applied to every handler. Checks `update.effective_user.id == config.TELEGRAM_OWNER_ID`. Unauthorized updates are silently dropped after logging at DEBUG (no user ID in log message).

### 4. Streaming Responses
- LLM responses are streamed via the `lmstudio` SDK's async generator. The bot progressively edits a single Telegram message using `message.edit_text()` every ~50 tokens or when a natural pause occurs, to stay within Telegram's rate limits.

### 5. Vision Model Detection
- After loading a model, `sdk.py` queries `client.llm.get_model_info()`. If the model's capabilities do not include vision, photo messages in that session are rejected with a user-friendly error.
