# Implementation Plan: Inline Button Menu Navigation

**Branch**: `002-inline-button-menu` | **Date**: 2026-04-11 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/002-inline-button-menu/spec.md`

## Summary

Add an inline button menu to the LMStudioBot Telegram bot. All existing slash-command functionality, including inference parity such as `/regenerate`, is accessible via tappable inline keyboard buttons grouped into five sections (Model Management, Chat Sessions, Settings, Inference, Help). Navigation edits a single persistent message in place — no additional chat messages. Free-text input prompts bridge the gap between button actions that need user-supplied values and the existing inference + CLI handlers.

**Technical approach**: One new file `src/bot/handlers/menu.py` contains all keyboard builders and a single `CallbackQueryHandler`. Per-conversation state (menu message ID, pending input action) lives in PTB's `context.chat_data`. The existing `text_message_handler` gains a `pending_input` check at the top to intercept input destined for menu actions, and the Inference sub-menu exposes both send and regenerate paths.

## Technical Context

**Language/Version**: Python 3.11+  
**Primary Dependencies**: `python-telegram-bot>=21.0` (`InlineKeyboardMarkup`, `InlineKeyboardButton`, `CallbackQueryHandler`), `lmstudio>=1.5.0`, `pydantic>=2.0`  
**Storage**: Ephemeral only (`context.chat_data`) — no new persistent storage  
**Testing**: pytest + pytest-asyncio (mode=auto), flake8 (line-length=100), black  
**Target Platform**: Windows / Linux (wherever Python 3.11+ runs)  
**Project Type**: Telegram bot (single-user, owner-only)  
**Performance Goals**: Navigation responses <500ms (edit_message_text is instant for owner-only single user)  
**Constraints**: No new pip dependencies; Telegram inline keyboard limits (100 total buttons, 8 per row); single persistent menu message per conversation  
**Scale/Scope**: 1 user; ~20 callback data keys; 2 new files; 4 updated files
